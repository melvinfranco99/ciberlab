Paso 0

Antes de empezar

CiberLab es una aplicación local: un pequeño servidor en tu equipo y ventanas de Brave en modo aplicación, una por escritorio. No sale nada a Internet salvo las descargas que tú pidas (imágenes Docker, ISOs).

Lo que necesitas instalado

zsh
# Comprueba que tienes todo
$ VBoxManage --version        # máquinas virtuales
$ docker --version            # laboratorios web
$ systemctl is-active docker  # debe decir «active»
$ df -h /                     # espacio libre

# Si Docker no está arrancado:
$ sudo systemctl enable --now docker
$ sudo usermod -aG docker $USER   # y cierra sesión para que aplique
Espacio en discoAhora mismo tienes unos 6–7 GB libres en /. Una Kali ocupa 20–30 GB. Antes de crear VMs grandes, libera espacio (por ejemplo sudo pacman -Sc y docker system prune) o guarda las VMs en tu partición grande de 832 GB.
La regla que no cambiaTodo lo que hagas con estas herramientas, hazlo solo contra tus propias máquinas del laboratorio o contra sistemas de un cliente que te haya dado autorización por escrito. En España, el acceso sin permiso es delito (art. 197 bis del Código Penal).

Paso 1

Activar el modo Ciberseguridad

Funciona igual que tus modos privado, paranoico y finanzas: un icono en la barra de polybar.

  1. Busca la calavera (☠, icono Nerd Font nf-md-skull) en el módulo de modos de la barra superior, junto a normal, privado, paranoico y finanzas.

  2. Clic izquierdo: activa el modo. Cambia el fondo de pantalla y abre un programa distinto en cada escritorio (tarda unos segundos). La calavera se pone en cian.

  3. Clic derecho: abre directamente el Laboratorio (máquinas virtuales), sin activar el modo completo.

  4. Muévete entre escritorios como siempre, por ejemplo con Super + 1…8.

Paso 2

Aprender con las lecciones

Cada escritorio tiene un temario dividido en niveles (principiante, intermedio, avanzado). Todas las lecciones siguen la misma estructura, así que en cuanto domines una sabes usar todas.

PartePara qué sirve
ObjetivoQué sabrás hacer al terminar.
TeoríaLo mínimo para entender el porqué.
Paso a pasoComandos con botón de copiar y la explicación de su salida.
DefensaCómo se detecta y cómo se protege lo que acabas de ver.
TestPreguntas con explicación de la respuesta correcta.
RetoUn ejercicio para hacer tú solo en el laboratorio.
ApuntesTu cuaderno; se guarda solo en ~/.local/share/ciberlab/.

Ejemplo: tu primera sesión de 45 minutos

  1. Ve al escritorio 1. En el panel de inicio pulsa Continuar en «Siguiente lección recomendada».

  2. Lee la teoría y ejecuta en tu terminal los comandos del paso a paso. Por ejemplo, en la lección de redes:

    zsh
    $ ip -br addr               # tus interfaces y sus IPs
lo        UNKNOWN  127.0.0.1/8
vboxnet0  UP       192.168.56.1/24      <- la red del laboratorio
$ ss -tulpn                 # qué puertos escucha tu equipo
tcp LISTEN 127.0.0.1:8766  users:(("python3",...))   <- CiberLab

  3. Responde el test. Si fallas, lee la explicación antes de seguir.

  4. Copia en Apuntes lo que te costó entender y pulsa Marcar como completada ✓. El progreso aparece en el panel de inicio.

TrucoLa barra de búsqueda de arriba busca en todas las lecciones y vulnerabilidades a la vez. Prueba con «ssh» o «XSS».

Paso 3

Tu red de laboratorio

Todas las prácticas ocurren en una red aislada que solo existe dentro de tu equipo. Ya la tienes creada.

esquema
            Internet
               │  (solo las VMs atacantes, por NAT)
   ┌───────────────┴───────────────┐
   │  Tu Arch  ·  vboxnet0 192.168.56.1   │
   └───────────────┬───────────────┘
                   │  red solo-anfitrión 192.168.56.0/24  (DHCP .101 – .254)
        ┌──────────┼──────────────┐
     Kali        ms2            Ubuntu / Windows
   NAT + lab   solo lab           solo lab
   (atacante)  (objetivo)        (objetivo / blue team)
  • Atacantes (Kali, Parrot, SIEM): dos tarjetas. NAT para descargar actualizaciones y la red del laboratorio para trabajar.
  • Objetivos (ms2, servidores, máquinas vulnerables): solo la red del laboratorio. Así una máquina vulnerable nunca queda expuesta a Internet ni a tu red de casa.
  • En el Laboratorio, el botón 🔒 Aislar deja una VM en modo objetivo y 🌐 Modo atacante la pasa a modo atacante (con la VM apagada).

Para comprobarla desde la terminal:

zsh
$ VBoxManage list hostonlyifs | grep -E 'Name|IPAddress|Status'
Name:            vboxnet0
IPAddress:       192.168.56.1
Status:          Up
$ VBoxManage showvminfo ms2 --machinereadable | grep '^nic'
nic1="hostonly"
nic2="none"

Paso 4

Primera práctica: reconocimiento de ms2

ms2 (Metasploitable 2) es una máquina Linux hecha para practicar, y ya está aislada. Vas a descubrirla en la red e inventariar sus servicios, igual que en la primera fase de una auditoría.

  1. Escritorio 8 → Laboratorio → Máquinas virtuales. En ms2 pulsa 📸 Snapshot y llámala limpia. Con ella podrás volver al estado original siempre.

  2. Pulsa ▶ Sin ventana (headless). En 30–60 segundos aparecerá su IP en la tabla, normalmente 192.168.56.101.

  3. Desde tu terminal, comprueba que responde y guarda los resultados en la carpeta de evidencias:

    zsh · ~/CiberLab/loot
    $ cd ~/CiberLab/loot && mkdir -p ms2 && cd ms2
$ ping -c 2 192.168.56.101
$ nmap -sn 192.168.56.0/24                       # ¿qué equipos hay en el laboratorio?
$ nmap -sV -T4 -oN servicios.txt 192.168.56.101  # puertos y versiones
PORT     STATE SERVICE     VERSION
21/tcp   open  ftp         vsftpd 2.3.4
22/tcp   open  ssh         OpenSSH 4.7p1 Debian 8ubuntu1
80/tcp   open  http        Apache httpd 2.2.8 ((Ubuntu) DAV/2)
3306/tcp open  mysql       MySQL 5.0.51a-3ubuntu5
...

  4. Piensa como un auditor. Para cada servicio, anota en tus apuntes si la versión está soportada y qué riesgo supone. Por ejemplo, «OpenSSH 4.7 y Apache 2.2.8 llevan más de 15 años sin soporte» es un hallazgo real de cualquier auditoría.

  5. Busca cada servicio en el escritorio 4 (Vulnerabilidades) y en la lección correspondiente, y sigue los labs guiados enlazados.

  6. Al terminar: ⏻ Apagar y, si has cambiado cosas, ⟲ Restaurar la instantánea limpia.

Credenciales de ms2Usuario msfadmin, contraseña msfadmin. Para entrar en su consola, arráncala con ▶ Iniciar (con ventana).

Paso 5

Crear tu máquina Kali

Kali será tu equipo de trabajo dentro del laboratorio. La forma más rápida es importar la imagen oficial para VirtualBox.

  1. Libera al menos 30 GB (ver Paso 0). Descarga de kali.org → Virtual Machines la imagen de VirtualBox y descomprímela en ~/CiberLab/isos/.

    zsh
    $ cd ~/CiberLab/isos
$ sha256sum kali-linux-*-virtualbox-amd64.7z   # compárala con la de la web
$ 7z x kali-linux-*-virtualbox-amd64.7z

  2. Laboratorio → ➕ Crear / importar VM → elige el fichero .vbox que se ha extraído. Para una ISO usa en su lugar Crear con la plantilla «Kali Linux (atacante)»: 4 GB de RAM, 2 CPU y 40 GB de disco.

  3. Con la VM apagada pulsa 🌐 Modo atacante. Así queda con NAT para Internet y con la red del laboratorio.

  4. Arráncala (usuario y contraseña kali / kali), cambia la contraseña y actualiza el sistema:

    kali
    kali$ passwd
kali$ sudo apt update && sudo apt full-upgrade -y
kali$ ip -br addr        # eth1 debería tener 192.168.56.x
kali$ ping -c 2 192.168.56.101   # ya ves a ms2

  5. Haz un 📸 Snapshot llamado recien-instalada.

¿Y un laboratorio de Active Directory?

Crea con las plantillas Windows Server 2022 Eval (controlador de dominio) y Windows 10 Eval (cliente). Las ISOs de evaluación de 180 días se descargan gratis del Evaluation Center de Microsoft. Las dos quedan solo en la red del laboratorio. Necesitas unos 100 GB y 8 GB de RAM libres.

¿Y un SIEM para el Blue Team?

La plantilla SIEM (8 GB de RAM, 80 GB de disco) está pensada para Wazuh o Security Onion. Instala el agente en las máquinas objetivo y verás sus eventos en el panel. Es el siguiente paso natural después de la práctica de logs del escritorio 5.

Paso 6

Labs web con Docker

Aplicaciones vulnerables a propósito que se arrancan en un clic. Solo escuchan en 127.0.0.1: nadie de tu red puede verlas.

LabDirecciónPara practicar
DVWA127.0.0.1:8081Lo clásico, con niveles de dificultad de low a impossible.
Juice Shop127.0.0.1:8082Tienda moderna con más de 100 retos del OWASP Top 10.
WebGoat127.0.0.1:8083Lecciones guiadas dentro de la propia app.
bWAPP127.0.0.1:8084Muchísimos tipos de fallo web.
VAmPI127.0.0.1:8085Seguridad de APIs REST.
DVGA127.0.0.1:8086Seguridad de GraphQL.
SSH target127.0.0.1:2222Bastionado de SSH y lectura de sus logs.

Ejemplo completo con DVWA

  1. Laboratorio → 🐳 Laboratorios Docker → DVWA → ▶ Iniciar. La primera vez descarga la imagen (1–2 minutos).

  2. Abre http://127.0.0.1:8081 y entra con admin / password. Pulsa Create / Reset Database y vuelve a entrar.

  3. En DVWA Security pon el nivel low. Abre la lección de hacking web que corresponda (escritorio 3) y haz el ejercicio en DVWA.

  4. Sube a medium y high. Al final mira el código del nivel impossible con el botón «View Source»: así se escribe la versión segura, que es lo que recomendarás en tus informes.

  5. Revisa lo que ha quedado registrado. Es justo lo que vería un analista del Blue Team:

    zsh
    $ docker logs ciberlab-dvwa 2>&1 | tail -20

  6. Pulsa Detener al terminar. El contenedor se borra y la próxima vez arranca limpio.

Paso 7

Catálogo de vulnerabilidades

El escritorio 4 tiene fichas de las vulnerabilidades más comunes (inyecciones, XSS, control de acceso, configuraciones por defecto, credenciales débiles, software sin parchear, etc.). Cada ficha tiene cuatro pestañas.

PestañaQué encuentras
Qué esExplicación sencilla, un ejemplo e impacto real para una empresa.
Dónde practicarQué lab de Docker, qué VM o qué plataforma guiada usar.
DetectarQué buscar en logs, herramientas de escaneo y señales en una auditoría.
DefensaCómo corregirlo y prevenirlo; es lo que pondrás en la recomendación del informe.

Ejemplo de flujo: en ms2 encontraste MySQL expuesto. Busca «credenciales» o «configuración» en el catálogo, lee Detectar y Defensa y escribe en tus apuntes la recomendación con tus palabras: «Restringir MySQL a localhost, eliminar usuarios sin contraseña, actualizar a una versión soportada».

Paso 8

Blue Team: aprender a leer logs

En el escritorio 5, la herramienta 🔎 Práctica de análisis de logs tiene tres incidentes simulados: un servidor Linux (auth.log), un servidor web (access.log) y eventos de Windows. Tienes que reconstruir lo ocurrido respondiendo preguntas.

  1. Elige el incidente de auth.log. Escribe en el filtro Failed password y observa qué IP aparece una y otra vez.

  2. Cambia el filtro a Accepted: ¿alguna de esas IPs llegó a entrar? ¿Con qué usuario?

  3. Busca lo que hizo después: useradd|sudo|wget|curl.

  4. Escribe las respuestas: al acertar aparece ✔ correcto (y tienes botón de pista). Descarga el .log y repite el análisis en la terminal, que es como lo harás de verdad:

    zsh
    # IPs con más intentos fallidos
$ grep 'Failed password' auth.log | grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' | sort | uniq -c | sort -rn | head
# ¿Entró alguna?
$ grep 'Accepted' auth.log
# Y en tu propio Arch, los intentos reales contra tu SSH (si lo tienes activo):
$ journalctl -u sshd --since today | grep -c 'Failed'
Para subir de nivelHaz lo mismo con el lab SSH target (puerto 2222). Prueba a entrar con una contraseña incorrecta varias veces y busca tus propios intentos con docker logs ciberlab-ssh-target. Después bastiona el servidor siguiendo la lección de SSH.

Paso 9

Hacer una auditoría de principio a fin

El programa Auditorías (escritorio 8) te guía desde el contrato hasta el informe. Los datos se guardan en ~/CiberLab/auditorias/. El ejemplo usa una empresa ficticia: haz tu primera auditoría contra tu propio laboratorio antes de hacer una para un cliente.

  1. Nueva auditoría. Pulsa ＋ Nueva auditoría. Ejemplo: cliente Panadería López S.L. (ficticio), tamaño pyme, tipo de prueba caja gris, alcance 192.168.1.0/24, router, NAS, web corporativa y correo. Fuera de alcance: TPV del banco.

  2. Autorización. Genera el documento con la plantilla, revísalo y no toques nada hasta tenerlo firmado por quien puede autorizarlo (el administrador o el gerente). Indica fechas, IPs, horario y persona de contacto para emergencias.

  3. Checklist. Al elegir pyme o gran empresa, la lista se adapta: una pyme no tiene SOC, pero sí copias de seguridad, router, Wi-Fi y correo. Marca cada punto como OK, fallo o no aplica. Un fallo se convierte en hallazgo con un clic.

  4. Hallazgos con CVSS. Un ejemplo realista:

    TítuloRouter de la oficina con la contraseña de administrador de fábrica
    VectorAV:A/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H
    Puntuación8.8 · Alta, la calcula la app al elegir el vector.
    EvidenciaCaptura del panel con la sesión iniciada, guardada en ~/CiberLab/loot/.
    RecomendaciónCambiar la contraseña por una única y larga, desactivar la administración remota y actualizar el firmware.

    No todo necesita CVSS. «No hay copias de seguridad fuera de la oficina» es una severidad media por riesgo de negocio, aunque no sea una vulnerabilidad técnica.

  5. Informe. En la pestaña Informe exporta a Markdown o HTML. Incluye un resumen ejecutivo para el gerente (sin jerga), una tabla de hallazgos por severidad y el detalle técnico. Guárdalo en ~/CiberLab/informes/ y entrégalo cifrado.

  6. Cierre. Archiva la auditoría cuando el cliente confirme las correcciones (se mueve a la papelera; no se borra). Para una gran empresa el proceso es el mismo con más pasos en la checklist: segmentación, Active Directory, SIEM, proveedores y cumplimiento (ENS, ISO 27001, NIS2).

Práctica recomendada: audita tu propio laboratorio

Crea la auditoría «Laboratorio casa», con alcance 192.168.56.0/24 y la autorización firmada por ti mismo. Escanea ms2, rellena la checklist y documenta cinco hallazgos con evidencia y CVSS. Exporta el informe. Es el mejor ejercicio para tu primer cliente real.

Paso 10

Plan de principiante a experto

Un orden razonable dedicando de 5 a 8 horas por semana. Cada fase usa varios escritorios.

Semanas 1–3Principiante

Escritorio 1 completo: Linux, redes TCP/IP, Bash. Escritorio 6 (redes) con Wireshark. Práctica: el reconocimiento de ms2 del Paso 4.

Semanas 4–6Principiante +

Escritorios 3 y 4: OWASP Top 10 con DVWA y Juice Shop. Complementa con la PortSwigger Web Security Academy (gratis).

Semanas 7–9Intermedio

Escritorio 5: la práctica de logs al 100 %, bastionado de un Ubuntu Server y un SIEM con Wazuh. Escritorio 7: seguridad de servidores y contenedores.

Semanas 10–12Intermedio +

Escritorio 2: metodología completa de pentesting en las rutas guiadas de TryHackMe o HTB Academy. Primera auditoría completa de tu laboratorio.

Mes 4–6Avanzado

Laboratorio de Active Directory (Windows Server + Windows 10), cloud (AWS/Azure) y auditorías de gran empresa. Certificación de entrada: eJPT o CompTIA Security+.

Mes 6+Experto

OSCP, PNPT o CRTP según tu rama (ofensiva o AD); BTL1 o CySA+ para defensa. Primeras auditorías reales para pymes con contrato y seguro de responsabilidad civil.

Si algo falla

Las ventanas no se abren o salen en blanco
zsh
$ cat $XDG_RUNTIME_DIR/ciberlab-server.log   # error del servidor
$ ss -tlnp | grep 8766                         # ¿otro programa usa el puerto?
$ ciberlab --stop && ciberlab                  # reiniciar
Una VM no recibe IP

Comprueba en el Laboratorio que su red es «Host-only (vboxnet0)». Si reiniciaste el equipo y vboxnet0 no aparece, pulsa Crear red de laboratorio otra vez o ejecuta sudo modprobe vboxnetadp vboxnetflt. Dentro de la VM, sudo dhclient eth0 fuerza la petición de IP.

Un lab Docker no arranca

Mira el registro con el botón Logs de su tarjeta o con docker logs ciberlab-dvwa. Suele ser falta de espacio (docker system df) o que el servicio Docker esté parado.

Quiero desinstalarlo
zsh
$ ciberlab-mode off
$ cp -p ~/.config/bspwm/bin/EnvMode.bak-ciberlab ~/.config/bspwm/bin/EnvMode
$ rm ~/.local/bin/ciberlab ~/.local/bin/ciberlab-mode

Tus auditorías en ~/CiberLab no se tocan.
